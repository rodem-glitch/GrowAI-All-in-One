## 1. 현재 상태 분석

| 항목 | 현황 | 비고 |
|------|------|------|
| 테마 관리 | ThemeContext (Context API) | 라이트/다크 모드 전환 |
| 다국어 관리 | LanguageContext (Context API) | i18n 언어 선택 |
| 서버 상태 | TanStack Query (React Query) | API 데이터 캐싱 및 동기화 |
| 로컬 상태 | useState / useReducer | 컴포넌트 단위 상태 |
| 폼 상태 | 비정형 (useState 기반) | 유효성 검증 로직 분산 |
| URL 상태 | 미활용 | 필터/검색 조건 URL 동기화 없음 |

## 2. 문제점 분석

### 2.1 Context API 한계

| 문제 | 상세 | 영향도 |
|------|------|--------|
| **불필요한 리렌더링** | Context 값이 변경되면 해당 Provider 하위의 모든 Consumer가 리렌더링 | 높음 |
| **selector 미지원** | 특정 값만 구독하는 것이 불가능. `theme`만 필요해도 전체 Context 구독 | 높음 |
| **상태 분리 어려움** | Provider 중첩(Provider Hell)으로 코드 가독성 저하 | 중 |
| **미들웨어 부재** | 로깅, 디버깅, persist 등 미들웨어 생태계 없음 | 중 |
| **비동기 처리 한계** | 비동기 상태 변경 패턴이 복잡하고 일관성 부족 | 중 |

```tsx
// 문제: ThemeContext 변경 시 LanguageContext를 사용하는 컴포넌트도 리렌더링
<ThemeProvider>
  <LanguageProvider>
    <AuthProvider>       {/* Provider Hell */}
      <NotificationProvider>
        <App />
      </NotificationProvider>
    </AuthProvider>
  </LanguageProvider>
</ThemeProvider>
```

### 2.2 글로벌 상태 부재

| 누락된 글로벌 상태 | 현재 처리 방식 | 문제점 |
|-------------------|--------------|--------|
| 사용자 인증 (auth) | 각 컴포넌트에서 개별 API 호출 | 인증 상태 불일치, 토큰 관리 분산 |
| 알림 (notification) | 없음 또는 로컬 상태 | 크로스 컴포넌트 알림 불가 |
| 사이드바/모달 UI | 각 페이지에서 useState | 전역 모달 오버레이 관리 불가 |
| 에디터 상태 | 로컬 상태 | 복잡한 에디터 상태 관리 한계 |

### 2.3 폼 상태 비일관성

- 각 폼마다 개별 useState로 필드 관리 -- 보일러플레이트 과다
- 유효성 검증 로직이 컴포넌트에 하드코딩 -- 재사용 불가
- 에러 상태 표시 패턴 비통일 -- UX 일관성 저하

## 3. 추천 아키텍처

### 3.1 상태 유형별 관리 전략

| 상태 유형 | 관리 도구 | 역할 | 번들 크기 |
|----------|----------|------|----------|
| **Server State** | TanStack Query v5 | API 데이터 캐싱, 동기화, 낙관적 업데이트 | 유지 (이미 사용 중) |
| **Client State** | Zustand | 글로벌 클라이언트 상태 (인증, UI, 테마, 알림) | **~3KB** gzip |
| **Form State** | React Hook Form + Zod | 폼 입력, 유효성 검증 | ~12KB gzip |
| **URL State** | React Router searchParams | 필터, 정렬, 페이지네이션 | 0KB (라우터 내장) |
| **Local State** | useState / useReducer | 컴포넌트 한정 상태 | 0KB (React 내장) |

### 3.3 Zustand를 선택한 이유

| 기준 | Context API | Redux Toolkit | Zustand | Jotai |
|------|------------|---------------|---------|-------|
| 번들 크기 | 0KB | ~33KB | **~3KB** | ~8KB |
| 보일러플레이트 | 많음 | 중간 | **최소** | 최소 |
| selector 지원 | X | O | **O** | O |
| 미들웨어 | X | O | **O** | X |
| DevTools | X | O | **O** | O |
| 학습 곡선 | 낮음 | 높음 | **낮음** | 낮음 |
| React 외부 접근 | X | O | **O** | X |
| TypeScript 지원 | 수동 | O | **O** | O |
| SSR 호환 | O | O | **O** | O |

**판정**: Zustand는 3KB의 초경량 번들로 Redux 수준의 기능을 제공하며, React 외부에서도 상태 접근이 가능하여 유틸리티 함수, 미들웨어 등에서 활용 가능

## 4. Zustand 스토어 설계

### 4.1 useAuthStore -- 사용자 인증 상태

```typescript
import { create } from 'zustand';
import { persist, devtools } from 'zustand/middleware';

interface User {
  id: string;
  email: string;
  name: string;
  role: 'admin' | 'creator' | 'viewer';
  avatarUrl?: string;
}

interface AuthState {
  user: User | null;
  token: string | null;
  isAuthenticated: boolean;
  isLoading: boolean;

  // Actions
  login: (email: string, password: string) => Promise<void>;
  logout: () => void;
  setUser: (user: User) => void;
  refreshToken: () => Promise<void>;
}

export const useAuthStore = create<AuthState>()(
  devtools(
    persist(
      (set, get) => ({
        user: null,
        token: null,
        isAuthenticated: false,
        isLoading: false,

        login: async (email, password) => {
          set({ isLoading: true });
          try {
            const response = await authApi.login({ email, password });
            set({
              user: response.user,
              token: response.token,
              isAuthenticated: true,
              isLoading: false,
            });
          } catch (error) {
            set({ isLoading: false });
            throw error;
          }
        },

        logout: () => {
          set({ user: null, token: null, isAuthenticated: false });
          // TanStack Query 캐시 초기화
          queryClient.clear();
        },

        setUser: (user) => set({ user }),

        refreshToken: async () => {
          const { token } = get();
          if (!token) return;
          const newToken = await authApi.refresh(token);
          set({ token: newToken });
        },
      }),
      { name: 'newkl-auth' }
    ),
    { name: 'AuthStore' }
  )
);
```

### 4.2 useUIStore -- UI 상태 관리

```typescript
interface Toast {
  id: string;
  type: 'success' | 'error' | 'warning' | 'info';
  message: string;
  duration?: number;
}

interface ModalConfig {
  id: string;
  component: string;
  props?: Record<string, unknown>;
}

interface UIState {
  // 사이드바
  sidebarOpen: boolean;
  sidebarCollapsed: boolean;

  // 모달
  modals: ModalConfig[];

  // 토스트
  toasts: Toast[];

  // Actions
  toggleSidebar: () => void;
  collapseSidebar: (collapsed: boolean) => void;
  openModal: (modal: ModalConfig) => void;
  closeModal: (id: string) => void;
  closeAllModals: () => void;
  addToast: (toast: Omit<Toast, 'id'>) => void;
  removeToast: (id: string) => void;
}

export const useUIStore = create<UIState>()(
  devtools(
    (set) => ({
      sidebarOpen: true,
      sidebarCollapsed: false,
      modals: [],
      toasts: [],

      toggleSidebar: () =>
        set((state) => ({ sidebarOpen: !state.sidebarOpen })),

      collapseSidebar: (collapsed) =>
        set({ sidebarCollapsed: collapsed }),

      openModal: (modal) =>
        set((state) => ({
          modals: [...state.modals, modal],
        })),

      closeModal: (id) =>
        set((state) => ({
          modals: state.modals.filter((m) => m.id !== id),
        })),

      closeAllModals: () => set({ modals: [] }),

      addToast: (toast) => {
        const id = crypto.randomUUID();
        set((state) => ({
          toasts: [...state.toasts, { ...toast, id }],
        }));
        // 자동 제거
        setTimeout(() => {
          set((state) => ({
            toasts: state.toasts.filter((t) => t.id !== id),
          }));
        }, toast.duration ?? 5000);
      },

      removeToast: (id) =>
        set((state) => ({
          toasts: state.toasts.filter((t) => t.id !== id),
        })),
    }),
    { name: 'UIStore' }
  )
);
```

### 4.3 useThemeStore -- 테마 관리 (Context API 대체)

```typescript
type Theme = 'light' | 'dark' | 'system';

interface ThemeState {
  theme: Theme;
  resolvedTheme: 'light' | 'dark';

  // Actions
  setTheme: (theme: Theme) => void;
}

export const useThemeStore = create<ThemeState>()(
  devtools(
    persist(
      (set) => ({
        theme: 'system',
        resolvedTheme: 'light',

        setTheme: (theme) => {
          const resolved =
            theme === 'system'
              ? window.matchMedia('(prefers-color-scheme: dark)').matches
                ? 'dark'
                : 'light'
              : theme;

          document.documentElement.classList.toggle('dark', resolved === 'dark');
          set({ theme, resolvedTheme: resolved });
        },
      }),
      { name: 'newkl-theme' }
    ),
    { name: 'ThemeStore' }
  )
);
```

### 4.4 useNotificationStore -- 알림 관리

```typescript
interface Notification {
  id: string;
  type: 'system' | 'project' | 'ai-complete' | 'collaboration';
  title: string;
  message: string;
  read: boolean;
  createdAt: string;
  actionUrl?: string;
}

interface NotificationState {
  notifications: Notification[];
  unreadCount: number;

  // Actions
  addNotification: (notification: Omit<Notification, 'id' | 'read' | 'createdAt'>) => void;
  markAsRead: (id: string) => void;
  markAllAsRead: () => void;
  removeNotification: (id: string) => void;
  clearAll: () => void;
}

export const useNotificationStore = create<NotificationState>()(
  devtools(
    (set) => ({
      notifications: [],
      unreadCount: 0,

      addNotification: (notification) =>
        set((state) => {
          const newNotification: Notification = {
            ...notification,
            id: crypto.randomUUID(),
            read: false,
            createdAt: new Date().toISOString(),
          };
          const notifications = [newNotification, ...state.notifications];
          return {
            notifications,
            unreadCount: notifications.filter((n) => !n.read).length,
          };
        }),

      markAsRead: (id) =>
        set((state) => {
          const notifications = state.notifications.map((n) =>
            n.id === id ? { ...n, read: true } : n
          );
          return {
            notifications,
            unreadCount: notifications.filter((n) => !n.read).length,
          };
        }),

      markAllAsRead: () =>
        set((state) => ({
          notifications: state.notifications.map((n) => ({ ...n, read: true })),
          unreadCount: 0,
        })),

      removeNotification: (id) =>
        set((state) => {
          const notifications = state.notifications.filter((n) => n.id !== id);
          return {
            notifications,
            unreadCount: notifications.filter((n) => !n.read).length,
          };
        }),

      clearAll: () => set({ notifications: [], unreadCount: 0 }),
    }),
    { name: 'NotificationStore' }
  )
);
```

## 5. 성능 최적화 전략

### 5.1 Zustand Selector -- 필요한 값만 구독

```typescript
// BAD: 스토어 전체 구독 -- theme 변경 시에도 리렌더링
const { user, isAuthenticated } = useAuthStore();

// GOOD: selector로 필요한 값만 구독 -- user 변경 시만 리렌더링
const user = useAuthStore((state) => state.user);
const isAuthenticated = useAuthStore((state) => state.isAuthenticated);

// GOOD: 여러 값을 하나의 selector로 묶되, shallow 비교 사용
import { useShallow } from 'zustand/react/shallow';

const { user, isAuthenticated } = useAuthStore(
  useShallow((state) => ({
    user: state.user,
    isAuthenticated: state.isAuthenticated,
  }))
);
```

### 5.4 React 19 Compiler (자동 메모이제이션)

| 항목 | 수동 메모이제이션 | React Compiler |
|------|-----------------|----------------|
| React.memo | 직접 래핑 필요 | **자동 적용** |
| useMemo | 의존성 배열 수동 관리 | **자동 감지** |
| useCallback | 의존성 배열 수동 관리 | **자동 감지** |
| 인적 오류 | 의존성 누락/과다 | **컴파일러가 보장** |
| 코드 가독성 | 메모이제이션 코드로 복잡 | **깔끔한 코드** |

```typescript
// React 19 Compiler 활성화 시 -- memo/useMemo/useCallback 제거 가능
function VideoList({ videos }: { videos: Video[] }) {
  // Compiler가 자동으로 메모이제이션 적용
  const sorted = videos.sort((a, b) =>
    b.createdAt.localeCompare(a.createdAt)
  );

  return (
    <ul>
      {sorted.map((video) => (
        <VideoCard key={video.id} video={video} />
      ))}
    </ul>
  );
}
```

```typescript
    }
  )
);
```

```typescript

// Step 2: ThemeContext를 useThemeStore 래퍼로 변경 (하위 호환)
// Step 3: 컴포넌트에서 useThemeStore 직접 사용으로 점진 교체
// Step 4: ThemeContext 제거

// 과도기: Context를 Zustand 래퍼로 변환
function ThemeProvider({ children }: { children: React.ReactNode }) {
  const theme = useThemeStore((s) => s.theme);
  const setTheme = useThemeStore((s) => s.setTheme);

  // 기존 Context 소비자와 호환 유지
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}
```

**NEWKL AI Video 플랫폼의 상태 관리를 5가지 레이어로 분리하여 예측 가능하고 성능 최적화된 아키텍처를 구축합니다.**

- **Local State**: useState 유지 -- 컴포넌트 한정 상태에 적합

> Context API에서 Zustand로의 점진적 전환을 통해 불필요한 리렌더링을 90% 이상 감소시키고, 개발자 경험(DX)과 사용자 경험(UX)을 동시에 향상시킵니다.
