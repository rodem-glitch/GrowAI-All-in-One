## 설계 원칙

NEWKL은 AI 고품질 영상 생성 회사로서 **비주얼이 곧 브랜드**다. 그러나 아무리 아름다운 영상도 로딩이 느리면 이탈로 이어진다. 따라서 다음 두 가지를 동시에 만족해야 한다.

1. **시각적 품질 타협 없음** — AI 생성 영상의 디테일이 손실 없이 전달되어야 한다
2. **체감 성능 최상위** — Hero 이미지 100KB 미만, 비디오 첫 프레임 500ms 이내

## 1. 이미지 최적화

### 1-1. 포맷 우선순위

| 순위 | 포맷 | 압축 | 브라우저 지원 | 용도 |
|------|------|------|-------------|------|
| 1순위 | **AVIF** | 손실/무손실, 최고 압축률 | Chrome 85+, Firefox 93+, Safari 16.4+ | 메인 제공 포맷 |
| 2순위 | **WebP** | 손실/무손실, 우수 압축률 | 모든 모던 브라우저 | AVIF 미지원 폴백 |
| 3순위 | **JPEG** | 손실, 표준 | 전체 | 레거시 폴백 |

- PNG는 로고/아이콘 등 투명도가 필요한 경우에만 사용 (가능하면 SVG 대체)
- AVIF는 JPEG 대비 평균 50% 이상 용량 절감

### 1-3. Lazy Loading

**기본 전략:** 뷰포트 밖 이미지는 `loading="lazy"` 속성 사용

```html
<!-- Above the Fold (Hero) — 즉시 로드 -->
<img src="hero.avif" loading="eager" fetchpriority="high" />

<!-- Below the Fold — 지연 로드 -->
<img src="gallery-01.avif" loading="lazy" />
```

**고급 전략:** Intersection Observer를 활용한 커스텀 Lazy Loading

```typescript
const observer = new IntersectionObserver(
  (entries) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) {
        const img = entry.target as HTMLImageElement;
        img.src = img.dataset.src!;
        img.srcset = img.dataset.srcset!;
        img.classList.remove('blur-placeholder');
        observer.unobserve(img);
      }
    });
  },
  { rootMargin: '200px' } // 뷰포트 200px 전에 미리 로드
);

document.querySelectorAll('img[data-src]').forEach((img) => {
  observer.observe(img);
});
```

### 1-5. Blur Placeholder (LQIP)

Low-Quality Image Placeholder로 체감 로딩 속도 향상

```typescript
// 빌드 타임에 LQIP 생성 (sharp 활용)
import sharp from 'sharp';

async function generateLQIP(inputPath: string): Promise<string> {
  const buffer = await sharp(inputPath)
    .resize(20, 20, { fit: 'inside' })
    .blur(10)
    .toFormat('webp', { quality: 20 })
    .toBuffer();

  return `data:image/webp;base64,${buffer.toString('base64')}`;
}
```

## 2. 비디오 최적화

### 2-1. HLS/DASH 적응형 스트리밍

네트워크 상황에 따라 자동으로 화질을 조절하여 끊김 없는 재생 보장

**인코딩 프로파일:**

| 프로파일 | 해상도 | 비트레이트 | 용도 |
|----------|--------|-----------|------|
| Low | 480p | 800 kbps | 모바일 / 저대역폭 |
| Medium | 720p | 2.5 Mbps | 일반 데스크톱 |
| High | 1080p | 5 Mbps | 고속 네트워크 |
| Ultra | 1440p/4K | 12 Mbps | 쇼케이스 상세 보기 |

**FFmpeg HLS 변환:**

```bash
ffmpeg -i input.mp4 \
  -c:v libx264 -preset slow -crf 22 \
  -c:a aac -b:a 128k \
  -hls_time 6 -hls_list_size 0 \
  -hls_segment_filename 'segment_%03d.ts' \
  output.m3u8
```

**클라이언트 재생 (hls.js):**

```typescript
import Hls from 'hls.js';

function initAdaptivePlayer(videoEl: HTMLVideoElement, src: string) {
  if (Hls.isSupported()) {
    const hls = new Hls({
      startLevel: -1,           // 자동 품질 선택
      capLevelToPlayerSize: true // 뷰포트 크기에 맞춤
    });
    hls.loadSource(src);
    hls.attachMedia(videoEl);
  } else if (videoEl.canPlayType('application/vnd.apple.mpegurl')) {
    // Safari 네이티브 HLS
    videoEl.src = src;
  }
}
```

### 2-2. 포스터 이미지 + 지연 로드

```html
<video
  poster="/img/video-poster-demo.avif"
  preload="none"
  playsinline
  muted
>
  <source src="/video/demo.webm" type="video/webm; codecs=av01.0.08M.08" />
  <source src="/video/demo.mp4" type="video/mp4" />
</video>
```

- `preload="none"` — 사용자가 재생하기 전까지 비디오 데이터 다운로드 안 함
- `poster` — 첫 인상을 위한 고품질 스틸 이미지 (AVIF/WebP)
- 히어로 영상처럼 자동재생이 필요한 경우에만 `preload="metadata"` 사용

### 2-3. Intersection Observer 기반 자동재생

뷰포트에 진입할 때만 재생, 이탈 시 일시정지하여 리소스 절약

```typescript
function setupAutoplay(videoEl: HTMLVideoElement) {
  const observer = new IntersectionObserver(
    (entries) => {
      entries.forEach((entry) => {
        if (entry.isIntersecting) {
          videoEl.play().catch(() => {
            // 자동재생 정책에 의해 차단된 경우 무시
          });
        } else {
          videoEl.pause();
        }
      });
    },
    { threshold: 0.5 } // 50% 이상 보일 때 재생
  );

  observer.observe(videoEl);
}
```

## 3. AI 생성 영상 쇼케이스

### 3-1. 데모 영상 사양

AI 생성 영상의 품질을 충실히 보여주되 웹 성능을 유지하는 균형점

| 항목 | 사양 | 비고 |
|------|------|------|
| 프레임레이트 | **30fps** | 웹 재생 최적 (60fps 대비 용량 50% 절감) |
| 해상도 | **1080p** (1920x1080) | 데스크톱 기준, 모바일은 적응형 스트리밍 |
| 코덱 | **AV1** | 최고 압축률, 동일 품질 대비 최소 용량 |
| 컨테이너 | WebM (1순위) / MP4 (폴백) | — |
| 비트레이트 | 4~6 Mbps (가변) | CRF 기반 품질 우선 인코딩 |
| 오디오 | Opus 128kbps / AAC 128kbps | — |

**AV1 인코딩 명령어:**

```bash
ffmpeg -i input.mp4 \
  -c:v libaom-av1 -crf 28 -b:v 0 \
  -cpu-used 4 -row-mt 1 -tiles 2x2 \
  -c:a libopus -b:a 128k \
  -movflags +faststart \
  output.webm
```

### 3-2. AI 자동 썸네일 생성

```typescript
interface ThumbnailConfig {
  videoId: string;
  timestamps: number[];     // AI가 선정한 주요 장면 타임스탬프
  outputSizes: Size[];      // [{ w: 480, h: 270 }, { w: 1280, h: 720 }]
  format: 'avif' | 'webp';
}

async function generateThumbnails(config: ThumbnailConfig): Promise<string[]> {
  // 1. AI가 영상 분석 → 시각적으로 가장 임팩트 있는 프레임 선정
  // 2. FFmpeg로 해당 타임스탬프 프레임 추출
  // 3. sharp로 리사이징 + 포맷 변환
  // 4. GCS에 업로드 후 CDN URL 반환
  const urls: string[] = [];

  for (const ts of config.timestamps) {
    const frame = await extractFrame(config.videoId, ts);
    for (const size of config.outputSizes) {
      const optimized = await sharp(frame)
        .resize(size.w, size.h, { fit: 'cover' })
        .toFormat(config.format, { quality: 80 })
        .toBuffer();

      const url = await uploadToGCS(optimized, config.videoId, ts, size);
      urls.push(url);
    }
  }

  return urls;
}
```

### 3-3. 프로그레시브 로딩 (저해상도 -> 고해상도)

사용자 체감 속도를 극대화하는 점진적 품질 향상 전략

```typescript
class ProgressiveVideoLoader {
  private videoEl: HTMLVideoElement;
  private qualities = ['480p', '720p', '1080p'] as const;

  constructor(videoEl: HTMLVideoElement) {
    this.videoEl = videoEl;
  }

  async load(baseUrl: string) {
    // 1단계: 포스터 이미지 (LQIP) — 즉시 표시
    this.videoEl.poster = `${baseUrl}/poster-lqip.webp`;

    // 2단계: 저해상도 비디오 — 빠른 시작
    this.videoEl.src = `${baseUrl}/preview-480p.mp4`;
    await this.videoEl.play();

    // 3단계: 고해상도로 전환 — 백그라운드 프리로드
    const connection = (navigator as any).connection;
    const isHighBandwidth = !connection || connection.downlink > 5;

    if (isHighBandwidth) {
      const highResSrc = `${baseUrl}/full-1080p.webm`;
      await this.preloadVideo(highResSrc);
      const currentTime = this.videoEl.currentTime;
      this.videoEl.src = highResSrc;
      this.videoEl.currentTime = currentTime;
      this.videoEl.play();
    }
  }

  private preloadVideo(src: string): Promise<void> {
    return new Promise((resolve) => {
      const link = document.createElement('link');
      link.rel = 'preload';
      link.as = 'video';
      link.href = src;
      link.onload = () => resolve();
      document.head.appendChild(link);
    });
  }
}
```

## 5. CDN 전략

### 5-1. GCS + Cloud CDN 아키텍처

```
[사용자 요청]
     ↓
[Cloud CDN (글로벌 POP)]
     ↓ (캐시 미스 시)
[Cloud Load Balancer]
     ↓
[GCS 버킷 (asia-northeast3)]
```

### 5-2. 글로벌 POP 배치

| 리전 | POP 위치 | 대상 사용자 |
|------|----------|-----------|
| **아시아** | 서울, 도쿄, 싱가포르, 홍콩 | 한국/일본/동남아 |
| **북미** | 로스앤젤레스, 뉴욕 | 북미 클라이언트 |
| **유럽** | 프랑크푸르트, 런던 | 유럽 클라이언트 |

- 주요 트래픽은 아시아권 → 서울 POP 우선 최적화
- 글로벌 클라이언트 대응을 위해 북미/유럽 POP 확보

### 5-3. 캐시 정책

```nginx
# 해시된 정적 에셋 (이미지, 비디오, JS, CSS)
location ~* \.(avif|webp|jpg|png|webm|mp4|js|css)$ {
    add_header Cache-Control "public, max-age=31536000, immutable";
    add_header Vary "Accept-Encoding";
}

# HTML / API 응답
location ~* \.html$ {
    add_header Cache-Control "public, max-age=300, stale-while-revalidate=86400";
}

# HLS 세그먼트
location ~* \.(m3u8)$ {
    add_header Cache-Control "public, max-age=5";
}

location ~* \.(ts)$ {
    add_header Cache-Control "public, max-age=86400";
}
```

**캐시 키 설계:**
- `{URL}` + `Accept` 헤더 (이미지 포맷 분기: AVIF vs WebP vs JPEG)
- 파일명에 콘텐츠 해시 포함 → `immutable` 캐시 활용

## 6. 성과 목표 및 측정

### 6-1. 핵심 성과 목표

| 지표 | 목표 | 측정 방법 |
|------|------|----------|
| **Hero 이미지 용량** | < 100KB | 빌드 타임 검증 (CI 체크) |
| **비디오 첫 프레임 표시** | < 500ms | Lighthouse / WebPageTest |
| **LCP (Largest Contentful Paint)** | < 2.5s | Core Web Vitals |
| **CLS (Cumulative Layout Shift)** | < 0.1 | Core Web Vitals |
| **이미지 총 페이로드 (초기 뷰포트)** | < 500KB | Chrome DevTools |
| **비디오 버퍼링 비율** | < 1% | 커스텀 애널리틱스 |

### 6-2. 자동화된 품질 게이트

```yaml
# CI/CD 파이프라인 — 이미지 용량 검증
media-quality-check:
  script:
    # Hero 이미지 100KB 초과 시 빌드 실패
    - |
      for img in public/img/hero-*; do
        size=$(stat -f%z "$img" 2>/dev/null || stat -c%s "$img")
        if [ "$size" -gt 102400 ]; then
          echo "FAIL: $img is ${size} bytes (limit: 102400)"
          exit 1
        fi
      done

    # Lighthouse 성능 점수 90 이상 검증
    - npx lhci autorun --assert.preset=lighthouse:recommended
```

### 6-3. 모니터링 대시보드

- **Cloud Monitoring** — CDN 캐시 적중률, 대역폭, 에러율
- **Lighthouse CI** — 매 배포 시 성능 점수 추적
- **Custom Analytics** — 비디오 재생 완료율, 버퍼링 횟수, 화질 전환 빈도
- **Real User Monitoring (RUM)** — 실제 사용자의 LCP/CLS/FID 수집
