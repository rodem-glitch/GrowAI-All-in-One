## 1. 인증 시스템

### 1.1 SSO (Single Sign-On) 소셜 로그인

| 제공자 | 프로토콜 | 용도 |
|--------|----------|------|
| Google | OAuth 2.0 / OpenID Connect | 일반 사용자, Google Workspace 연동 |
| Microsoft | OAuth 2.0 / MSAL | 기업 사용자, Azure AD 연동 |
| Apple | Sign in with Apple | iOS/macOS 사용자 |

- NextAuth.js (Auth.js) 기반 통합 인증 레이어 구성
- 각 Provider별 콜백 URL 및 스코프 관리
- 신규 가입 시 이메일 기반 계정 자동 병합 (동일 이메일 → 동일 계정)

### 1.2 JWT + Refresh Token

```
[클라이언트] ──── Access Token (Bearer) ────→ [API Gateway]
     │                                              │
     │←── HttpOnly Secure Cookie (Refresh Token) ───│
```

| 항목 | 설정 |
|------|------|
| Access Token 유효기간 | 15분 |
| Refresh Token 유효기간 | 7일 (슬라이딩 윈도우) |
| Refresh Token 저장 | HttpOnly + Secure + SameSite=Strict Cookie |
| 토큰 서명 알고리즘 | RS256 (비대칭 키) |
| 키 로테이션 | 90일 주기, JWK Set 엔드포인트 제공 |

- Access Token은 메모리 저장 (localStorage/sessionStorage 사용 금지)
- Refresh Token 탈취 대비: Token Rotation + Reuse Detection
- 로그아웃 시 서버 측 Refresh Token 즉시 무효화 (블랙리스트)

### 1.3 MFA (Multi-Factor Authentication)

- **TOTP 기반**: Google Authenticator, Microsoft Authenticator 호환
- RFC 6238 준수, SHA-1/SHA-256 지원
- 백업 코드 10개 발급 (일회용, 해시 저장)
- 관리자 계정: MFA 필수 적용
- 일반 사용자: MFA 권장 (보안 등급에 따라 강제 가능)

## 2. API 보안

### 2.1 CORS (Cross-Origin Resource Sharing)

```python
# FastAPI CORS 설정 예시
ALLOWED_ORIGINS = [
    "https://growai.newkl.com",
    "https://admin.growai.newkl.com",
    "https://studio.growai.newkl.com",
]

app.add_middleware(
    CORSMiddleware,
    allow_origins=ALLOWED_ORIGINS,       # 화이트리스트 기반
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "DELETE", "PATCH"],
    allow_headers=["Authorization", "Content-Type", "X-Request-ID"],
    max_age=3600,
)
```

- 와일드카드(`*`) 사용 절대 금지
- 개발 환경: `localhost:3000`, `localhost:8000`만 허용
- Preflight 캐시: 1시간

### 2.2 Rate Limiting

| 서비스 | 제한 | 윈도우 | 비고 |
|--------|------|--------|------|
| 인증 API (로그인/회원가입) | 10 req | 1분 | 브루트포스 방지 |
| 일반 API | 100 req | 1분 | 사용자별 |
| AI 생성 API | 20 req | 1분 | 비용 관리 |
| 파일 업로드 | 50 req | 1시간 | 용량 제한 병행 |
| 관리자 API | 200 req | 1분 | IP 기반 추가 제한 |

- Redis 기반 슬라이딩 윈도우 카운터 구현
- 429 응답 시 `Retry-After` 헤더 포함
- 초과 시 점진적 백오프 적용

### 2.3 API Key 관리

- **GCP Secret Manager** 활용하여 모든 시크릿 중앙 관리
- 환경별 시크릿 분리: `dev/`, `staging/`, `prod/` 프리픽스
- 시크릿 자동 로테이션: 90일 주기
- 애플리케이션 레벨 캐싱 (TTL: 5분)
- 접근 로그 Cloud Audit Logs 통합

```

│   ├── anthropic-api-key

    └── ...
```

### 2.4 Input Validation

| 계층 | 도구 | 역할 |
|------|------|------|
| 프론트엔드 | **Zod** | 폼 입력값 실시간 검증, 타입 추론 |
| API Gateway | **JSON Schema** | 요청 페이로드 구조 검증 |
| 백엔드 | **Pydantic v2** | 데이터 모델 검증, 직렬화/역직렬화 |
| 데이터베이스 | **CHECK 제약조건** | 최종 데이터 무결성 보장 |

- 모든 입력: 최대 길이 제한, 허용 문자셋 정의
- SQL Injection 방지: SQLAlchemy ORM 파라미터 바인딩 필수
- Path Traversal 방지: 파일 경로 정규화 및 화이트리스트 검증

## 3. XSS/CSRF 방어

### 3.1 Content-Security-Policy (CSP)

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-{random}';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https://storage.googleapis.com;
  font-src 'self' https://fonts.gstatic.com;
  connect-src 'self' https://api.growai.newkl.com wss://ws.growai.newkl.com;
  media-src 'self' https://storage.googleapis.com;
  frame-ancestors 'none';
  base-uri 'self';
  form-action 'self';
  upgrade-insecure-requests;
```

- 인라인 스크립트: nonce 기반 허용 (해시 방식 병행)
- `eval()` 사용 완전 차단
- CSP 위반 보고: `report-uri` 엔드포인트 운영

### 3.2 보안 헤더

| 헤더 | 값 | 목적 |
|------|-----|------|
| `X-Frame-Options` | `DENY` | 클릭재킹 방지 |
| `X-Content-Type-Options` | `nosniff` | MIME 스니핑 방지 |
| `X-XSS-Protection` | `0` | 브라우저 내장 필터 비활성화 (CSP로 대체) |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 리퍼러 정보 제한 |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` | 브라우저 기능 제한 |

### 3.3 SameSite Cookie

```
Set-Cookie: refresh_token=...; 
  HttpOnly; 
  Secure; 
  SameSite=Strict; 
  Path=/api/auth; 
  Max-Age=604800;
  Domain=.growai.newkl.com
```

- 인증 쿠키: `SameSite=Strict` (크로스 사이트 전송 완전 차단)
- 일반 세션 쿠키: `SameSite=Lax` (GET 요청만 허용)
- CSRF Token: Double Submit Cookie 패턴 적용

### 3.4 DOMPurify (사용자 입력 Sanitize)

```typescript
import DOMPurify from 'dompurify';

// 사용자 입력 HTML 정화
const sanitizeConfig = {
  ALLOWED_TAGS: ['b', 'i', 'em', 'strong', 'p', 'br', 'ul', 'ol', 'li'],
  ALLOWED_ATTR: ['class'],
  FORBID_TAGS: ['script', 'iframe', 'object', 'embed'],
  FORBID_ATTR: ['onerror', 'onclick', 'onload', 'style'],
};

const cleanHTML = DOMPurify.sanitize(userInput, sanitizeConfig);
```

- AI 생성 콘텐츠 출력 시에도 반드시 sanitize 적용
- Rich Text Editor 입력: 서버 측 2차 검증 필수

## 4. HTTPS/TLS

### 4.1 TLS 1.3 필수

| 항목 | 설정 |
|------|------|
| 최소 TLS 버전 | TLS 1.3 |
| 암호 스위트 | TLS_AES_256_GCM_SHA384, TLS_CHACHA20_POLY1305_SHA256 |
| TLS 1.0/1.1 | 완전 비활성화 |
| TLS 1.2 | 레거시 클라이언트 지원 시에만 허용 (제한적) |

### 4.2 HSTS (HTTP Strict Transport Security)

```
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
```

- `max-age`: 1년 (31,536,000초)
- `includeSubDomains`: 모든 서브도메인 HTTPS 강제
- `preload`: HSTS Preload List 등록 (브라우저 내장)
- HTTP → HTTPS 301 리다이렉트 설정

### 4.3 Certificate Transparency (CT)

- Google Certificate Transparency 로그 등록 필수
- `Expect-CT` 헤더 설정 (enforce 모드)
- 인증서 발급 모니터링: 무단 발급 시 알림
- 인증서 관리: GCP Certificate Manager 또는 Let's Encrypt (자동 갱신)

| 비밀번호 | Argon2id (해싱) | N/A (단방향) |

- 암호화 키 로테이션: 연 1회 이상
- 키 접근 로그: Cloud Audit Logs 기록
- 암호화 키와 데이터 분리 저장

## 6. 프론트엔드 보안

### 6.1 환경변수 관리

```
# .env.local (클라이언트 노출 변수)
NEXT_PUBLIC_API_URL=https://api.growai.newkl.com
NEXT_PUBLIC_GA_ID=G-XXXXXXXXXX

# .env (서버 전용 — 절대 클라이언트 노출 금지)
DATABASE_URL=postgresql://...
JWT_SECRET=...
OPENAI_API_KEY=sk-...
```

- `NEXT_PUBLIC_` 접두사 변수만 클라이언트 번들에 포함
- 서버 전용 시크릿은 절대 클라이언트 코드에서 참조 불가
- CI/CD 파이프라인에서 환경변수 주입 (하드코딩 금지)
- `.env` 파일 `.gitignore` 등록 필수

### 6.2 Source Map 관리

| 환경 | Source Map | 설정 |
|------|-----------|------|
| 개발 | 활성화 | `devtool: 'eval-source-map'` |
| 스테이징 | 서버 전용 | Sentry 업로드 후 삭제 |
| 프로덕션 | **비활성화** | `productionBrowserSourceMaps: false` |

- 프로덕션 빌드에서 source map 파일 완전 제거
- 에러 추적: Sentry에 source map 별도 업로드 (비공개)

### 6.3 Subresource Integrity (SRI)

```html
<script 
  src="https://cdn.example.com/lib.js" 
  integrity="sha384-oqVuAfXRKap7fdgcCY5uykM6+R9GqQ8K/uxy9rx7HNQlGYl1kPzQho1wx4JwY8wC"
  crossorigin="anonymous">
</script>
```

- 외부 CDN 리소스 로드 시 SRI 해시 검증 필수
- 해시 불일치 시 리소스 로드 차단
- 자체 호스팅 우선, CDN 사용 최소화

## 7. 보안 모니터링

### 7.1 SIEM (Security Information and Event Management)

```
[로그 소스]                    [수집/분석]              [대응]
```

- 관리자 작업 감사 로그 (누가, 언제, 무엇을)
- 로그 보존: 최소 1년, 변조 방지 (Cloud Storage WORM)

### 7.2 침입 탐지 (IDS/IPS)

| 탐지 항목 | 임계값 | 대응 |
|-----------|--------|------|
| 로그인 실패 반복 | 5회/5분 | 계정 잠금 (30분) |
| 비정상 IP 접근 | 알려진 악성 IP | 즉시 차단 |
| SQL Injection 시도 | 패턴 매칭 | 요청 차단 + 알림 |
| 대량 데이터 조회 | 1000건 이상/분 | 속도 제한 + 알림 |
| 비인가 API 접근 | 403 반복 | IP 차단 + 알림 |

- GCP Cloud Armor WAF 적용 (OWASP Top 10 규칙셋)
- Cloud IDS 활성화 (네트워크 레벨 침입 탐지)

### 7.3 이상 행동 감지

| 감지 항목 | 설명 | 대응 |
|-----------|------|------|
| 비정상 지역 로그인 | 평소와 다른 국가/지역에서 접속 | MFA 재인증 요구 |
| 동시 세션 이상 | 다수 기기에서 동시 로그인 | 사용자 알림 + 확인 |
| 대량 다운로드 | 비정상적 콘텐츠 대량 다운로드 | 다운로드 제한 + 알림 |
| API 사용 패턴 이상 | 정상 범위를 벗어난 API 호출 | 속도 제한 + 조사 |
| 권한 상승 시도 | 비인가 관리자 기능 접근 시도 | 즉시 차단 + 보고 |

- 머신러닝 기반 사용자 행동 프로파일링 (Cloud Security AI)
- 실시간 알림: Slack, PagerDuty, 이메일 다채널 전송
- 주간 보안 리포트 자동 생성
