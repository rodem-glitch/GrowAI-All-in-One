## 루트 파일

| 파일 | 설명 |
|------|------|
| `package.json` | 프로젝트 메타데이터와 통합 의존성 관리. React, React Router, Tailwind CSS, Vite 등 모든 패키지를 하나의 `package.json`에서 관리한다. |
| `vite.config.ts` | Vite 번들러 설정. 개발 서버 포트, 프록시, 플러그인(React SWC), 빌드 최적화 옵션을 정의한다. |
| `tsconfig.json` | TypeScript 컴파일러 옵션. strict 모드 활성화, 경로 별칭(`@/` 등), JSX 설정을 포함한다. |
| `index.html` | SPA(Single Page Application) 진입점. Vite가 이 파일을 기준으로 `src/main.tsx`를 로드한다. |

## src/ - 소스 코드

### 진입 파일

| 파일 | 역할 |
|------|------|
| `main.tsx` | React DOM 루트를 생성하고 `<App />`을 마운트하는 애플리케이션 시작점. BrowserRouter 등 전역 프로바이더를 감싼다. |
| `App.tsx` | 통합 라우터 정의. 포털 허브(`/`), LearnForm(`/learnform`), LMS(`/lms/*`) 등 모든 TLA 서비스의 라우트를 하나의 React Router 설정으로 관리한다. |
| `index.css` | Tailwind CSS 디렉티브(`@tailwind base/components/utilities`)와 프로젝트 전용 커스텀 스타일을 포함하는 글로벌 스타일시트. |

---

### src/contexts/ - React Context 프로바이더

전역 상태를 Context API로 관리하는 프로바이더 모음이다.

| 파일 | 역할 |
|------|------|
| `ThemeContext.tsx` | 다크모드/라이트모드 전환과 액센트 컬러 관리. `useTheme()` 훅을 통해 앱 전체에서 테마 상태에 접근할 수 있다. |
| `LanguageContext.tsx` | 한국어/영어 다국어 전환 관리. `useLanguage()` 훅으로 현재 언어와 번역 함수(`t()`)를 제공한다. |

---

### src/i18n/ - 국제화(다국어) 파일

| 파일 | 역할 |
|------|------|
| `ko.ts` | 한국어 번역 문자열 정의. 키-값 쌍으로 모든 UI 텍스트를 관리한다. |
| `en.ts` | 영어 번역 문자열 정의. `ko.ts`와 동일한 키 구조를 유지한다. |
| `index.ts` | 번역 파일을 통합 내보내기(export)하는 배럴 파일. |

### src/components/ - 컴포넌트

재사용 가능한 React 컴포넌트를 역할별로 분류한다.

#### components/layout/ - 레이아웃 컴포넌트

앱의 전체 골격을 구성하는 레이아웃 요소들이다.

| 컴포넌트 | 역할 |
|----------|------|
| `Header` | 상단 네비게이션 바. 로고, 메뉴, 사용자 프로필 영역 포함 |
| `Footer` | 하단 푸터. 링크, 저작권 정보 표시 |
| `TopNav` | 상단 탭 네비게이션. 서비스 간 전환 UI |
| `Layout` | 페이지 공통 레이아웃 래퍼. Header + 콘텐츠 영역 + Footer를 조합 |
| `Logo` | GrowAI 로고 컴포넌트 |
| `Mobile` | 모바일 반응형 메뉴/네비게이션 |
| `Profile` | 사용자 프로필 드롭다운/아바타 |

#### components/sections/ - 랜딩 페이지 섹션

LearnForm 랜딩 페이지를 구성하는 12개 섹션 컴포넌트이다.

- `Hero` - 메인 히어로 배너
- `Features` - 주요 기능 소개
- `HowItWorks` - 작동 방식 설명
- `Pricing` - 요금제 안내
- `Testimonials` - 사용자 후기
- `CTA` - 행동 유도(Call-to-Action) 배너
- 그 외 6개 섹션으로 구성

#### components/ui/ - UI 원자(Atoms) 컴포넌트

디자인 시스템의 가장 작은 단위 컴포넌트이다.

| 컴포넌트 | 역할 |

여러 도메인에서 공유하는 중간 수준의 컴포넌트이다.

### src/data/ - 목업/데모 데이터

개발 및 프로토타이핑 단계에서 사용하는 정적 데이터 파일이다. 강의 목록, 사용자 정보, 학습 경로 등의 샘플 데이터를 TypeScript 객체 또는 JSON으로 관리한다. 백엔드 API가 완성되면 점진적으로 실제 API 호출로 교체한다.

---

### src/hooks/ - 커스텀 훅

React 커스텀 훅 모음이다. 컴포넌트에서 반복되는 로직을 훅으로 추출하여 재사용성을 높인다. 예시로 `useMediaQuery`, `useDebounce`, `useLocalStorage` 등이 위치한다.

---

### src/services/ - API 서비스 레이어

백엔드 API와의 통신을 담당하는 서비스 모듈이다. `fetch` 또는 `axios` 기반의 API 클라이언트를 정의하고, 각 도메인(강의, 사용자, 프로젝트 등)별로 서비스 함수를 분리한다. 인증 토큰 관리, 에러 핸들링, 요청/응답 인터셉터 등을 포함한다.

---

### src/styles/ - 추가 스타일

`index.css`에 포함하기 어려운 추가 스타일 파일을 관리한다. 컴포넌트별 CSS 모듈, 애니메이션 정의, 테마 변수 등이 위치한다.

## 디렉토리 설계 원칙

1. **역할 기반 분류**: 컴포넌트를 `layout`, `ui`, `common`, `course`, `social` 등 역할별로 분류하여 탐색성을 높인다.
2. **TLA 기반 페이지 구조**: `pages/` 하위에 TLA 서비스별 디렉토리를 두어 서비스 간 경계를 명확히 한다.
3. **관심사 분리**: Context(상태), Hook(로직), Service(API), Component(UI), Page(라우트)를 각각 독립 디렉토리로 분리한다.
4. **점진적 확장**: 플레이스홀더 패턴으로 아직 구현되지 않은 TLA 서비스도 라우트를 미리 확보하고, 향후 구현 시 해당 디렉토리에 페이지를 추가한다.
5. **단일 진입점**: `App.tsx`에서 모든 라우트를 통합 관리하여 SPA로서의 일관성을 유지한다.
