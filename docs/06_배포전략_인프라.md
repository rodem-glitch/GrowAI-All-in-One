# 06. 배포 전략 및 인프라

## 1. 빌드 시스템

### Vite 6 기반 SPA 빌드

GrowAI 프론트엔드는 Vite 6를 사용하여 SPA(Single Page Application)로 빌드된다.

### 코드 스플리팅

- `React.lazy()` + `<Suspense>`를 활용한 라우트 단위 지연 로딩
- 초기 로딩 시 필요한 코드만 다운로드하여 성능 최적화

```tsx
const Dashboard = lazy(() => import('./pages/Dashboard'));
const Learn = lazy(() => import('./pages/Learn'));
const Review = lazy(() => import('./pages/Review'));
```

### 청크 분할 전략

`vite.config.ts`의 `manualChunks` 설정을 통해 벤더 라이브러리를 분리한다.

| 청크 이름 | 포함 라이브러리 | 목적 |
|-----------|----------------|------|
| `react-vendor` | react, react-dom, react-router | React 코어 (변경 빈도 낮음) |
| `ui-vendor` | UI 컴포넌트 라이브러리 | UI 프레임워크 |
| `i18n-vendor` | i18next, react-i18next | 다국어 지원 |

### CSS 코드 분할

- 각 라우트별 CSS가 해당 JS 청크와 함께 분할 로딩
- Tailwind CSS의 사용하지 않는 클래스는 빌드 시 제거 (PurgeCSS)

## 2. 도커 컨테이너화

### Dockerfile: 멀티 스테이지 빌드

```dockerfile
# Stage 1: 빌드
FROM node:20-alpine AS builder
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile
COPY . .
RUN pnpm build

# Stage 2: 서빙
FROM nginx:alpine AS production
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### docker-compose.yml

```yaml
version: "3.8"
services:
  frontend:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "80:80"
    depends_on:
      - api

  api:
    build:
      context: ./apps/api
      dockerfile: Dockerfile
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=${DATABASE_URL}
      - REDIS_URL=${REDIS_URL}
      - GEMINI_API_KEY=${GEMINI_API_KEY}
    depends_on:
      - db
      - redis

  db:
    image: postgres:16-alpine
    volumes:
      - pgdata:/var/lib/postgresql/data
    environment:
      - POSTGRES_DB=growai
      - POSTGRES_USER=${DB_USER}
      - POSTGRES_PASSWORD=${DB_PASSWORD}

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  pgdata:
```

## 3. Nginx 설정

```nginx
server {
    listen 80;
    server_name growai.co.kr;
    root /usr/share/nginx/html;
    index index.html;

    # gzip 압축
    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css application/json application/javascript
               text/xml application/xml application/xml+rss text/javascript
               image/svg+xml;

    # 정적 자산 캐시 (1년)
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # index.html 캐시 방지
    location = /index.html {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
        add_header Pragma "no-cache";
        add_header Expires "0";
    }

    # API 프록시
    location /api/ {
        proxy_pass http://api:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # SPA fallback - 모든 경로를 index.html로
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

## 4. 도메인 설정

### 도메인 구조

- **growai.co.kr** -- 단일 SPA 진입점

### 클라이언트 사이드 라우팅

모든 TLA(Three Letter Acronym) 라우트는 클라이언트 사이드에서 처리된다.

| 경로 | 설명 |
|------|------|
| `/` | 랜딩 페이지 |
| `/dashboard` | 대시보드 |
| `/learn/:id` | 학습 페이지 |
| `/review/:id` | 복습 페이지 |
| `/login` | 로그인 |
| `/register` | 회원가입 |

Nginx의 `try_files $uri /index.html` 설정으로 모든 경로가 SPA로 전달되므로, 새로고침 시에도 정상 동작한다.

## 5. GCP 배포

### 아키텍처 개요

```
사용자 → Cloud Load Balancer → Cloud Run (Frontend/Nginx)
                                    ↓
                              Cloud Run (FastAPI)
                                    ↓
                    ┌───────────────┼───────────────┐
                    ↓               ↓               ↓
              AlloyDB          Memorystore        GCS
            (PostgreSQL)        (Redis)       (정적 자산)
```

### Cloud Run 컨테이너

- 프론트엔드와 API를 각각 별도의 Cloud Run 서비스로 배포
- 자동 스케일링: 최소 0, 최대 인스턴스 수 설정
- 콜드 스타트 최소화를 위한 최소 인스턴스 1개 유지 (프로덕션)

### Cloud Build CI/CD

```yaml
# cloudbuild.yaml
steps:
  # 테스트 실행
  - name: 'node:20'
    entrypoint: 'bash'
    args:
      - '-c'
      - |
        corepack enable
        pnpm install --frozen-lockfile
        pnpm test

  # Docker 이미지 빌드
  - name: 'gcr.io/cloud-builders/docker'
    args: ['build', '-t', 'gcr.io/$PROJECT_ID/growai-frontend', '.']

  # Container Registry에 푸시
  - name: 'gcr.io/cloud-builders/docker'
    args: ['push', 'gcr.io/$PROJECT_ID/growai-frontend']

  # Cloud Run에 배포
  - name: 'gcr.io/google.com/cloudsdktool/cloud-sdk'
    args:
      - 'gcloud'
      - 'run'
      - 'deploy'
      - 'growai-frontend'
      - '--image=gcr.io/$PROJECT_ID/growai-frontend'
      - '--region=asia-northeast3'
      - '--platform=managed'
```

### AlloyDB (PostgreSQL)

- Google의 PostgreSQL 호환 관리형 데이터베이스
- 리전: `asia-northeast3` (서울)
- 자동 백업 및 포인트인타임 복구 지원
- 읽기 전용 복제본으로 읽기 성능 확장 가능

### Memorystore (Redis)

- 세션 관리 및 캐싱
- Celery 태스크 브로커
- AI 체인 중간 결과 임시 저장

### GCS (Google Cloud Storage)

- 사용자 업로드 자산 저장
- AI 생성 콘텐츠 저장
- CDN 연동을 통한 정적 자산 서빙

## 6. 환경 변수

### 필수 환경 변수

| 변수명 | 설명 | 예시 |
|--------|------|------|
| `GEMINI_API_KEY` | Google Gemini API 인증 키 | `AIza...` |
| `DATABASE_URL` | PostgreSQL 연결 문자열 | `postgresql+asyncpg://user:pass@host:5432/growai` |
| `REDIS_URL` | Redis 연결 문자열 | `redis://host:6379/0` |

### 환경별 관리

- **로컬 개발**: `.env` 파일 (`.gitignore`에 포함)
- **CI/CD**: Cloud Build 시크릿 매니저 연동
- **프로덕션**: GCP Secret Manager를 통한 안전한 시크릿 관리

```bash
# GCP Secret Manager에 시크릿 등록
gcloud secrets create GEMINI_API_KEY --data-file=./gemini-key.txt
gcloud secrets create DATABASE_URL --data-file=./db-url.txt
gcloud secrets create REDIS_URL --data-file=./redis-url.txt
```

## 7. 모니터링

### Cloud Monitoring

- Cloud Run 인스턴스 CPU/메모리 사용량 모니터링
- 커스텀 메트릭: API 응답 시간, AI 체인 처리 시간
- 알림 정책: 에러율 5% 초과 시 Slack/이메일 알림

### Error Reporting

- 애플리케이션 에러 자동 수집 및 그룹화
- Python (FastAPI) 및 JavaScript (프론트엔드) 에러 추적
- 에러 발생 시 실시간 알림

### Performance Tracing

- Cloud Trace를 통한 분산 추적
- API 요청 → AI 체인 → DB 쿼리 전 구간 추적
- 병목 지점 식별 및 최적화

```python
# FastAPI에 Cloud Trace 연동 예시
from opentelemetry import trace
from opentelemetry.exporter.cloud_trace import CloudTraceSpanExporter

tracer = trace.get_tracer(__name__)

@app.get("/api/v1/projects/{project_id}")
async def get_project(project_id: str):
    with tracer.start_as_current_span("get_project"):
        # DB 조회
        with tracer.start_as_current_span("db_query"):
            project = await db.get(project_id)
        return project
```

### 대시보드 구성

| 대시보드 | 주요 지표 |

| AI 처리 | 체인 실행 시간, 토큰 사용량, 성공/실패율 |
