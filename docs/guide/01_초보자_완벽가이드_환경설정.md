## 1. 사전 지식

### 1.1 이 가이드를 읽기 전에 알아야 할 것

이 가이드에서는 터미널에 명령어를 입력하는 방식으로 개발 환경을 구축합니다.
아래 개념을 먼저 이해하고 진행하세요.

| 개념 | 설명 |
|------|------|
| **터미널(Terminal)** | 컴퓨터에 텍스트로 명령을 내리는 창입니다. 윈도우의 "명령 프롬프트(cmd)"와 비슷하며, Ubuntu에서는 `Ctrl + Alt + T`로 열 수 있습니다. |
| **CLI(Command Line Interface)** | 마우스 클릭 대신 키보드로 명령을 입력하는 방식입니다. 예: `ls`를 입력하면 현재 폴더의 파일 목록이 출력됩니다. |
| **패키지 매니저** | 프로그램을 설치하고 관리하는 도구입니다. Ubuntu는 `apt`, JavaScript는 `npm`/`pnpm`, Python은 `pip`/`uv`를 사용합니다. 스마트폰의 앱스토어와 비슷한 역할입니다. |
| **Git** | 코드의 변경 이력을 기록하는 버전 관리 도구입니다. 문서 작성 시 "되돌리기(Ctrl+Z)"를 무한히 사용할 수 있는 것과 비슷합니다. 여러 사람이 동시에 같은 코드를 수정할 때 충돌을 방지해줍니다. |
| **Docker** | 프로그램을 "컨테이너"라는 상자에 넣어서 어떤 컴퓨터에서든 동일하게 실행되도록 만드는 기술입니다. "내 컴퓨터에서는 되는데 서버에서는 안 돼요" 문제를 해결합니다. |

### 1.2 용어 사전 (가나다/ABC 순)

이 프로젝트에서 자주 등장하는 용어를 쉽게 설명합니다. 모르는 단어가 나올 때마다 돌아와서 확인하세요.

| 용어 | 설명 |
|------|------|
| **API (Application Programming Interface)** | 프로그램끼리 데이터를 주고받는 약속된 방법입니다. 식당의 "메뉴판"과 같아서, 어떤 요청을 보내면 어떤 결과가 돌아오는지 정의합니다. 예: "사용자 목록을 달라"고 요청하면 JSON 형식으로 사용자 데이터가 돌아옵니다. |
| **CDN (Content Delivery Network)** | 전 세계 여러 서버에 콘텐츠(이미지, CSS, JS 등)를 복사해두고, 사용자와 가장 가까운 서버에서 전달하는 기술입니다. 한국 사용자가 미국 서버 대신 한국 서버에서 파일을 받으면 훨씬 빠릅니다. |
| **CLI (Command Line Interface)** | 텍스트 명령어로 컴퓨터를 조작하는 방식입니다. GUI(그래픽 인터페이스)의 반대 개념으로, 마우스 대신 키보드만 사용합니다. 개발자들이 자동화와 효율성을 위해 선호합니다. |
| **Cloud Run** | Google Cloud의 서버리스 컨테이너 실행 서비스입니다. Docker 컨테이너를 올려두면 요청이 올 때만 실행되고, 사용한 만큼만 비용을 냅니다. 서버 관리가 필요 없어 편리합니다. |
| **Container (컨테이너)** | 애플리케이션과 실행에 필요한 모든 것(코드, 라이브러리, 설정)을 하나의 패키지로 묶은 것입니다. Docker가 대표적인 컨테이너 기술입니다. 이삿짐을 박스에 넣어 운반하는 것과 비슷합니다. |
| **CSS (Cascading Style Sheets)** | 웹 페이지의 색상, 글꼴, 레이아웃 등 "디자인"을 담당하는 언어입니다. HTML이 뼈대라면 CSS는 옷과 화장입니다. |
| **Docker** | 컨테이너를 만들고 실행하는 플랫폼입니다. 개발 환경을 통째로 "이미지"로 만들어서 누구든 동일한 환경에서 코드를 실행할 수 있게 합니다. |
| **Edge** | 사용자에게 물리적으로 가까운 서버에서 코드를 실행하는 방식입니다. CDN과 비슷하지만, 단순 파일 전달이 아니라 로직(코드)도 실행할 수 있습니다. |
| **Framework (프레임워크)** | 애플리케이션 개발을 위한 뼈대/틀입니다. 집을 지을 때 철근 구조물처럼, 기본 구조를 제공하고 개발자는 그 위에 살을 붙입니다. Next.js, FastAPI 등이 프레임워크입니다. |
| **Git** | 코드 변경 이력을 관리하는 분산 버전 관리 시스템입니다. `commit`으로 저장하고, `branch`로 분기하고, `merge`로 합칩니다. GitHub은 Git 저장소를 온라인으로 호스팅하는 서비스입니다. |
| **GPU (Graphics Processing Unit)** | 원래 그래픽 처리용이지만, 대량의 병렬 연산에 뛰어나 AI/ML 학습에 필수적입니다. AI 모델 학습 시 CPU보다 수십 배 빠릅니다. |
| **gRPC** | Google이 만든 고성능 원격 프로시저 호출(RPC) 프레임워크입니다. REST API보다 빠르고 효율적이며, 마이크로서비스 간 통신에 주로 사용됩니다. Protocol Buffers라는 데이터 직렬화 형식을 사용합니다. |
| **HMR (Hot Module Replacement)** | 코드를 수정하면 브라우저를 새로고침하지 않아도 변경된 부분만 즉시 반영되는 기능입니다. 개발 속도를 크게 높여줍니다. |
| **HTTP (HyperText Transfer Protocol)** | 웹에서 데이터를 주고받는 기본 통신 규약입니다. 브라우저가 서버에 "이 페이지 보여줘"라고 요청(request)하면 서버가 응답(response)을 보냅니다. |
| **i18n (Internationalization)** | 소프트웨어를 여러 언어로 사용할 수 있게 만드는 과정입니다. "internationalization"의 i와 n 사이에 18글자가 있어서 i18n이라 부릅니다. 한국어, 영어, 일본어 등 다국어 지원을 의미합니다. |
| **JSON (JavaScript Object Notation)** | 데이터를 저장하고 전달하는 텍스트 형식입니다. 사람도 읽을 수 있고 컴퓨터도 쉽게 처리할 수 있습니다. 예: `{"name": "홍길동", "age": 30}` |
| **JWT (JSON Web Token)** | 사용자 인증 정보를 담은 암호화된 토큰입니다. 로그인 후 서버가 JWT를 발급하면, 이후 요청마다 이 토큰을 보내서 "나는 로그인한 사용자"임을 증명합니다. 놀이공원 입장 팔찌와 비슷합니다. |
| **LLM (Large Language Model)** | GPT-4, Claude 같은 대규모 언어 모델입니다. 방대한 텍스트 데이터로 학습하여 사람처럼 글을 읽고, 쓰고, 대화할 수 있습니다. GrowAI의 핵심 AI 엔진입니다. |
| **MCP (Model Context Protocol)** | AI 모델이 외부 도구나 데이터에 접근할 수 있게 해주는 표준 프로토콜입니다. LLM이 데이터베이스를 조회하거나 API를 호출할 때 사용됩니다. |
| **Node.js** | JavaScript를 브라우저 밖에서도 실행할 수 있게 해주는 런타임 환경입니다. 서버 개발, CLI 도구, 빌드 도구 등에 사용됩니다. Chrome의 V8 엔진을 기반으로 합니다. |
| **npm (Node Package Manager)** | Node.js의 기본 패키지 매니저입니다. 전 세계 개발자들이 만든 라이브러리를 설치하고 관리합니다. `npm install 패키지명`으로 설치합니다. pnpm은 npm의 개선판입니다. |
| **ORM (Object-Relational Mapping)** | 데이터베이스 테이블을 프로그래밍 언어의 객체로 다루는 기술입니다. SQL 쿼리를 직접 작성하는 대신 Python/JavaScript 코드로 DB를 조작할 수 있습니다. SQLAlchemy가 대표적입니다. |
| **PostgreSQL** | 강력한 오픈소스 관계형 데이터베이스입니다. MySQL보다 고급 기능이 많고, 대규모 데이터 처리에 뛰어납니다. GrowAI는 GCP의 AlloyDB(PostgreSQL 호환)를 사용합니다. |
| **React** | Facebook이 만든 UI(사용자 인터페이스) 라이브러리입니다. 웹 페이지를 "컴포넌트"라는 작은 조각으로 나눠서 만듭니다. 레고 블록처럼 조합하여 복잡한 화면을 구성합니다. |
| **Redis** | 메모리에 데이터를 저장하는 초고속 데이터베이스입니다. 캐시(자주 쓰는 데이터 임시 저장), 세션 관리, 메시지 큐 등에 사용됩니다. 디스크 DB보다 100배 이상 빠릅니다. |
| **REST (Representational State Transfer)** | 웹 API를 설계하는 규칙/스타일입니다. HTTP 메서드(GET, POST, PUT, DELETE)를 사용하여 자원(데이터)을 다룹니다. 대부분의 웹 서비스가 REST API를 제공합니다. |
| **SPA (Single Page Application)** | 페이지 전체를 새로고침하지 않고, 필요한 부분만 바꾸는 웹 애플리케이션입니다. Gmail, Google Maps 같은 앱이 SPA입니다. React/Next.js로 만듭니다. |
| **SQL (Structured Query Language)** | 데이터베이스에서 데이터를 조회하고 관리하는 언어입니다. `SELECT * FROM users WHERE age > 20` 처럼 영어와 비슷한 문법으로 데이터를 다룹니다. |
| **SSE (Server-Sent Events)** | 서버가 클라이언트에게 실시간으로 데이터를 보내는 기술입니다. WebSocket보다 간단하며, AI 응답을 한 글자씩 스트리밍할 때 사용합니다. ChatGPT의 타이핑 효과가 SSE입니다. |
| **SSR (Server-Side Rendering)** | 서버에서 HTML을 미리 만들어서 브라우저에 보내는 방식입니다. 검색엔진 최적화(SEO)와 초기 로딩 속도에 유리합니다. Next.js의 핵심 기능입니다. |
| **SSG (Static Site Generation)** | 빌드 시점에 HTML 파일을 미리 생성하는 방식입니다. SSR보다 빠르지만, 실시간 데이터 반영이 어렵습니다. 블로그, 문서 사이트에 적합합니다. |
| **Tailwind CSS** | CSS를 클래스 이름으로 직접 작성하는 유틸리티 퍼스트 CSS 프레임워크입니다. `class="text-blue-500 font-bold"`처럼 HTML에 바로 스타일을 적용합니다. 별도 CSS 파일이 필요 없어 빠르게 개발할 수 있습니다. |
| **TypeScript** | JavaScript에 "타입(type)"을 추가한 언어입니다. 변수가 숫자인지 문자인지 미리 정의하여 실수를 방지합니다. JavaScript의 상위 집합이므로 JS 코드가 그대로 동작합니다. |
| **UI/UX** | UI(User Interface)는 사용자가 보는 화면 디자인, UX(User Experience)는 사용자가 느끼는 전체 경험입니다. 버튼 색상은 UI, 버튼을 눌렀을 때의 편리함은 UX입니다. |
| **Vector DB (벡터 데이터베이스)** | 텍스트, 이미지 등을 수학적 벡터로 변환하여 저장하고, 의미적 유사도로 검색하는 DB입니다. "사과와 비슷한 과일"을 검색하면 "배, 복숭아"가 나옵니다. AI 검색(RAG)의 핵심입니다. |
| **Vite** | 차세대 프론트엔드 빌드 도구입니다. Webpack보다 10-100배 빠르며, HMR을 지원합니다. "비트"라고 읽습니다 (프랑스어로 "빠르다"는 뜻). |
| **WebSocket** | 클라이언트와 서버 간 양방향 실시간 통신을 위한 기술입니다. HTTP는 요청-응답 방식이지만, WebSocket은 연결을 유지하며 양쪽에서 자유롭게 데이터를 주고받습니다. 채팅, 실시간 알림에 사용됩니다. |

## 2. Ubuntu LTS 기본 설정

> 아래 명령어를 터미널에 한 줄씩 복사하여 붙여넣고 Enter를 누르세요.
> `#`으로 시작하는 줄은 설명(주석)이므로 입력하지 않아도 됩니다.

### 2.1 시스템 업데이트

시스템을 최신 상태로 만들고, 개발에 필요한 기본 도구를 설치합니다.

```bash
# ──────────────────────────────────────────────────────────────
# 1단계: 패키지 목록 업데이트
# 어떤 프로그램들이 있고 최신 버전이 무엇인지 목록을 갱신합니다
# (프로그램 자체를 설치하는 것이 아니라, "카탈로그"를 최신으로 바꾸는 과정)
# ──────────────────────────────────────────────────────────────
sudo apt update

# ──────────────────────────────────────────────────────────────
# 2단계: 설치된 모든 프로그램을 최신 버전으로 업그레이드
# -y 옵션: "정말 업그레이드할까요?" 질문에 자동으로 "예" 응답
# ──────────────────────────────────────────────────────────────
sudo apt upgrade -y

# ──────────────────────────────────────────────────────────────
# 3단계: 기본 개발 도구 설치
# build-essential : C/C++ 컴파일러 등 빌드에 필요한 기본 도구 모음
# curl            : URL로 데이터를 다운로드하는 명령어 도구
# wget            : curl과 비슷한 다운로드 도구 (대용량 파일에 적합)
# git             : 코드 버전 관리 도구
# unzip           : .zip 파일 압축 해제 도구
# software-properties-common : PPA(추가 저장소) 관리 도구
# ──────────────────────────────────────────────────────────────
sudo apt install -y build-essential curl wget git unzip software-properties-common

# ──────────────────────────────────────────────────────────────
# 4단계: 설치 확인 (각 명령어가 버전 번호를 출력하면 성공)
# ──────────────────────────────────────────────────────────────
git --version     # 예: git version 2.43.0
curl --version    # 예: curl 8.5.0 ...
```

### 2.2 Git 초기 설정

Git을 처음 사용할 때 사용자 정보를 등록해야 합니다.

```bash
# ──────────────────────────────────────────────────────────────
# Git에 이름 등록 (커밋할 때 "누가 수정했는지" 기록됨)
# "Your Name" 부분을 본인 이름으로 변경하세요
# ──────────────────────────────────────────────────────────────
git config --global user.name "Your Name"

# ──────────────────────────────────────────────────────────────
# Git에 이메일 등록 (GitHub 계정 이메일과 동일하게 설정 권장)
# ──────────────────────────────────────────────────────────────
git config --global user.email "your.email@example.com"

# ──────────────────────────────────────────────────────────────
# 기본 브랜치 이름을 "main"으로 설정 (최신 관례)
# ──────────────────────────────────────────────────────────────
git config --global init.defaultBranch main

# ──────────────────────────────────────────────────────────────
# 설정 확인 (등록한 이름과 이메일이 보이면 성공)
# ──────────────────────────────────────────────────────────────
git config --global --list
```

### 2.3 Node.js 설치 (JavaScript 실행 환경)

Node.js는 JavaScript를 브라우저 없이 실행할 수 있게 해주는 환경입니다.
nvm(Node Version Manager)을 사용하면 여러 버전의 Node.js를 쉽게 설치하고 전환할 수 있습니다.

```bash
# ──────────────────────────────────────────────────────────────
# 1단계: nvm(Node Version Manager) 설치
# nvm은 Node.js 버전을 쉽게 관리하는 도구입니다
# 여러 프로젝트에서 다른 Node.js 버전을 사용할 때 유용합니다
# ──────────────────────────────────────────────────────────────
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.0/install.sh | bash

# ──────────────────────────────────────────────────────────────
# 2단계: 터미널 설정 다시 불러오기
# nvm 설치 스크립트가 ~/.bashrc에 설정을 추가했으므로
# 이를 현재 터미널에 반영합니다
# ──────────────────────────────────────────────────────────────
source ~/.bashrc

# ──────────────────────────────────────────────────────────────
```

### 2.7 Docker 설치

Docker는 애플리케이션을 컨테이너로 패키징하여 어디서든 동일하게 실행되도록 합니다.
개발, 테스트, 배포 환경의 차이를 없애줍니다.

```bash
# ══════════════════════════════════════════════════════════════
# Docker 설치 (공식 문서 기반, 2026년 기준)
# ══════════════════════════════════════════════════════════════

# ──────────────────────────────────────────────────────────────
# 1단계: Docker 설치에 필요한 사전 패키지 설치
# ca-certificates : SSL 인증서 관련 도구 (HTTPS 통신용)
# gnupg           : GNU 프라이버시 가드 (보안 키 관리)
# ──────────────────────────────────────────────────────────────
sudo apt install -y ca-certificates gnupg

# ──────────────────────────────────────────────────────────────
# 2단계: Docker 공식 GPG 키 설치
# GPG 키: 소프트웨어가 진짜 Docker에서 배포한 것인지 확인하는 "인증서"
# 악성 소프트웨어 설치를 방지하기 위한 보안 절차입니다
# ──────────────────────────────────────────────────────────────
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# ──────────────────────────────────────────────────────────────
# 3단계: Docker 공식 저장소를 apt 소스에 추가
# Ubuntu 기본 저장소에는 오래된 Docker가 있을 수 있으므로
# Docker 공식 저장소를 직접 추가하여 최신 버전을 설치합니다
# ──────────────────────────────────────────────────────────────
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# ──────────────────────────────────────────────────────────────
# 4단계: 패키지 목록 갱신 (Docker 저장소 반영)
# ──────────────────────────────────────────────────────────────
sudo apt update

# ──────────────────────────────────────────────────────────────
# 5단계: Docker 엔진 및 관련 도구 설치
# docker-ce          : Docker Community Edition (메인 엔진)
# docker-ce-cli      : Docker 명령어 도구 (docker 명령어)
# containerd.io      : 컨테이너 런타임 (Docker의 핵심 엔진)
# docker-buildx-plugin   : 멀티 플랫폼 빌드 플러그인
# docker-compose-plugin  : 여러 컨테이너를 한 번에 관리하는 도구
# ──────────────────────────────────────────────────────────────
sudo apt install -y \
  docker-ce \
  docker-ce-cli \
  containerd.io \
  docker-buildx-plugin \
  docker-compose-plugin

# ──────────────────────────────────────────────────────────────
# 6단계: 현재 사용자를 docker 그룹에 추가
# 기본적으로 docker 명령은 sudo(관리자 권한)가 필요합니다
# docker 그룹에 추가하면 sudo 없이 docker를 사용할 수 있습니다
# ──────────────────────────────────────────────────────────────
sudo usermod -aG docker $USER

# ──────────────────────────────────────────────────────────────
# 7단계: 그룹 변경을 현재 세션에 적용
# (또는 터미널을 닫고 다시 열어도 됩니다)
# ──────────────────────────────────────────────────────────────
newgrp docker

# ──────────────────────────────────────────────────────────────
# 8단계: Docker 설치 확인
# docker --version         → Docker version 26.x.x 출력되면 성공
# docker compose version   → Docker Compose version v2.x.x 출력되면 성공
# ──────────────────────────────────────────────────────────────
docker --version
docker compose version

# ──────────────────────────────────────────────────────────────
# 9단계: Docker 정상 작동 테스트
# hello-world 이미지를 다운로드하고 실행합니다
# "Hello from Docker!" 메시지가 출력되면 Docker가 정상 동작하는 것입니다
# ──────────────────────────────────────────────────────────────
docker run hello-world
```

## 3. GCP 프로젝트 초기 설정

> 이 과정은 **프로젝트당 한 번만** 수행하면 됩니다.

### 3.1 프로젝트 생성

```bash
# ──────────────────────────────────────────────────────────────
# 1단계: 새 GCP 프로젝트 생성
# growai-prod        : 프로젝트 ID (전 세계에서 고유해야 함)
# --name             : 프로젝트 표시 이름 (콘솔에 보이는 이름)
```

### 3.2 필요한 API 활성화

GCP에서는 서비스(API)를 사용하기 전에 먼저 "활성화"해야 합니다.
전등의 스위치를 켜는 것과 비슷합니다. 활성화만으로는 비용이 발생하지 않습니다.

```bash
# ──────────────────────────────────────────────────────────────
# 사용할 GCP 서비스들의 API를 한 번에 활성화합니다
# 각 서비스의 역할을 주석으로 설명합니다
# ──────────────────────────────────────────────────────────────

# Cloud Run: 서버리스 컨테이너 실행 서비스
# Docker 컨테이너를 올리면 자동으로 서버가 구성됩니다
gcloud services enable run.googleapis.com

# Cloud Build: CI/CD (코드 푸시 시 자동 빌드/배포)
# GitHub에 코드를 올리면 자동으로 빌드하고 Cloud Run에 배포합니다
gcloud services enable cloudbuild.googleapis.com

# Artifact Registry: Docker 이미지 저장소
# 빌드한 Docker 이미지를 저장하고 관리합니다 (DockerHub의 GCP 버전)
gcloud services enable artifactregistry.googleapis.com

# Cloud SQL: 관리형 PostgreSQL 데이터베이스
# 데이터베이스 서버를 직접 관리하지 않아도 됩니다
gcloud services enable sqladmin.googleapis.com

# AlloyDB: 고성능 PostgreSQL 호환 데이터베이스 (Cloud SQL보다 빠름)
gcloud services enable alloydb.googleapis.com

# Memorystore: 관리형 Redis 서비스
# 캐시, 세션 관리, 작업 큐에 사용됩니다
gcloud services enable redis.googleapis.com

# Cloud Storage: 파일 저장소 (이미지, 동영상, 문서 등)
# AWS의 S3와 동일한 역할입니다
gcloud services enable storage.googleapis.com

# Vertex AI: Google의 AI/ML 플랫폼
# Gemini 모델 호출, 임베딩 생성 등에 사용됩니다
gcloud services enable aiplatform.googleapis.com

# Secret Manager: 비밀 키 관리 서비스
# API 키, DB 비밀번호 등을 안전하게 저장합니다
# 코드에 비밀번호를 직접 작성하지 않아도 됩니다
gcloud services enable secretmanager.googleapis.com

# Cloud Monitoring: 서비스 상태 모니터링
# CPU 사용률, 메모리, 에러 발생 등을 대시보드로 확인합니다
gcloud services enable monitoring.googleapis.com

# Cloud Logging: 서비스 로그 수집
# 애플리케이션의 로그(기록)를 중앙에서 관리하고 검색합니다
gcloud services enable logging.googleapis.com

# Cloud Pub/Sub: 비동기 메시지 전달 서비스
# 서비스 간 이벤트 기반 통신에 사용됩니다
gcloud services enable pubsub.googleapis.com

# Cloud Tasks: 비동기 작업 큐
# 시간이 오래 걸리는 작업을 백그라운드에서 처리합니다
gcloud services enable cloudtasks.googleapis.com

# ──────────────────────────────────────────────────────────────
# 활성화된 API 목록 확인
# ──────────────────────────────────────────────────────────────
gcloud services list --enabled
```

### 3.3 서비스 계정 설정

서비스 계정은 사람이 아닌 프로그램이 GCP에 접근할 때 사용하는 "신분증"입니다.
사람은 Google 계정으로 로그인하지만, 프로그램은 서비스 계정으로 인증합니다.

```bash
# ──────────────────────────────────────────────────────────────
# 1단계: 서비스 계정 생성
# growai-app : 서비스 계정 ID (프로젝트 내에서 고유)
# --display-name : 사람이 읽기 쉬운 이름
# ──────────────────────────────────────────────────────────────
gcloud iam service-accounts create growai-app \
  --display-name="GrowAI Application Service Account"

# ──────────────────────────────────────────────────────────────
# 2단계: 서비스 계정에 필요한 권한(역할) 부여
# 각 역할이 어떤 권한을 주는지 주석으로 설명합니다
# ──────────────────────────────────────────────────────────────

# Cloud Run 관리자: Cloud Run 서비스를 배포하고 관리할 수 있는 권한
gcloud projects add-iam-policy-binding growai-prod \
  --member="serviceAccount:growai-app@growai-prod.iam.gserviceaccount.com" \
  --role="roles/run.admin"

# Cloud SQL 클라이언트: Cloud SQL 데이터베이스에 접속할 수 있는 권한
gcloud projects add-iam-policy-binding growai-prod \
  --member="serviceAccount:growai-app@growai-prod.iam.gserviceaccount.com" \
  --role="roles/cloudsql.client"

# Cloud Storage 관리자: 파일 업로드/다운로드/삭제 권한
gcloud projects add-iam-policy-binding growai-prod \
  --member="serviceAccount:growai-app@growai-prod.iam.gserviceaccount.com" \
  --role="roles/storage.admin"

# Secret Manager 접근자: 저장된 비밀 키를 읽을 수 있는 권한
gcloud projects add-iam-policy-binding growai-prod \
  --member="serviceAccount:growai-app@growai-prod.iam.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"

# Vertex AI 사용자: AI 모델을 호출할 수 있는 권한
gcloud projects add-iam-policy-binding growai-prod \
  --member="serviceAccount:growai-app@growai-prod.iam.gserviceaccount.com" \
  --role="roles/aiplatform.user"

# 로그 작성자: 로그를 Cloud Logging에 기록할 수 있는 권한
gcloud projects add-iam-policy-binding growai-prod \
  --member="serviceAccount:growai-app@growai-prod.iam.gserviceaccount.com" \
  --role="roles/logging.logWriter"

# Pub/Sub 편집자: 메시지를 보내고 받을 수 있는 권한
gcloud projects add-iam-policy-binding growai-prod \
  --member="serviceAccount:growai-app@growai-prod.iam.gserviceaccount.com" \
  --role="roles/pubsub.editor"

# ──────────────────────────────────────────────────────────────
# 3단계: 서비스 계정 키 파일 다운로드 (로컬 개발용)
#
# 주의: 이 키 파일은 절대 Git에 커밋하거나 외부에 공유하면 안 됩니다!
#       .gitignore에 반드시 추가하세요
#
# 프로덕션 환경에서는 키 파일 대신 Workload Identity를 사용합니다
# ──────────────────────────────────────────────────────────────
gcloud iam service-accounts keys create ~/growai-key.json \
  --iam-account=growai-app@growai-prod.iam.gserviceaccount.com

# ──────────────────────────────────────────────────────────────
# 4단계: 키 파일 권한 설정 (본인만 읽을 수 있도록)
# 600 = 소유자만 읽기/쓰기 가능, 다른 사용자는 접근 불가
# ──────────────────────────────────────────────────────────────
chmod 600 ~/growai-key.json

# ──────────────────────────────────────────────────────────────
# 5단계: 환경변수 설정
# GOOGLE_APPLICATION_CREDENTIALS 환경변수에 키 파일 경로를 지정하면
# Google 라이브러리들이 자동으로 이 키를 사용하여 인증합니다
# ──────────────────────────────────────────────────────────────
echo '' >> ~/.bashrc
echo '# GCP 서비스 계정 인증 키 경로' >> ~/.bashrc
echo 'export GOOGLE_APPLICATION_CREDENTIALS=$HOME/growai-key.json' >> ~/.bashrc
source ~/.bashrc

# ──────────────────────────────────────────────────────────────
# 6단계: 인증 확인
# 서비스 계정 목록에 growai-app이 보이면 성공
# ──────────────────────────────────────────────────────────────
gcloud iam service-accounts list
```

### 3.4 Artifact Registry 저장소 생성

Docker 이미지를 저장할 저장소를 만듭니다.
빌드한 Docker 이미지를 여기에 업로드하고, Cloud Run이 여기서 이미지를 가져와 실행합니다.

```bash
# ──────────────────────────────────────────────────────────────
# Docker 이미지 저장소 생성
# growai-repo       : 저장소 이름
# --repository-format=docker : Docker 이미지 형식
# --location=asia-northeast3 : 서울 리전
# --description     : 저장소 설명
# ──────────────────────────────────────────────────────────────
gcloud artifacts repositories create growai-repo \
  --repository-format=docker \
  --location=asia-northeast3 \
  --description="GrowAI Docker images"

# ──────────────────────────────────────────────────────────────
# Docker가 Artifact Registry에 접근할 수 있도록 인증 설정
# 이 명령 실행 후 docker push/pull이 GCP 저장소와 연동됩니다
# ──────────────────────────────────────────────────────────────
gcloud auth configure-docker asia-northeast3-docker.pkg.dev

# ──────────────────────────────────────────────────────────────
# 저장소 생성 확인
# ──────────────────────────────────────────────────────────────
gcloud artifacts repositories list --location=asia-northeast3
```

## 5. 자주 발생하는 문제와 해결법

### 5.1 "permission denied" 오류

```bash
# 원인: 파일이나 명령에 실행 권한이 없음
# 해결: sudo를 앞에 붙이거나, 사용자 권한 확인

# Docker 관련 "permission denied"인 경우:
# docker 그룹에 사용자가 추가되지 않았을 수 있음
sudo usermod -aG docker $USER
newgrp docker

# 파일 실행 권한 부여:
# chmod +x 파일명
```

### 5.2 "command not found" 오류

```bash
# 원인: 프로그램이 설치되지 않았거나 PATH에 등록되지 않음
# 해결: 설치 확인 후 PATH 확인

# 어떤 프로그램이 어디에 설치되어 있는지 확인
which node       # /home/사용자/.nvm/versions/node/v22.x.x/bin/node
which python3.12 # /usr/bin/python3.12
which go         # /usr/local/go/bin/go

# PATH 환경변수 확인 (프로그램 검색 경로 목록)
echo $PATH

# PATH에 추가되지 않은 경우 ~/.bashrc에 추가
# 예: echo 'export PATH=$PATH:/추가할/경로' >> ~/.bashrc
# 추가 후 반드시 source ~/.bashrc 실행
```

### 5.3 nvm/node가 새 터미널에서 작동하지 않음

```bash
# 원인: ~/.bashrc에 nvm 설정이 제대로 추가되지 않았을 수 있음
# 해결: nvm 설정 확인

# ~/.bashrc 파일 끝부분에 아래 내용이 있는지 확인
# 없으면 수동으로 추가하세요:
cat >> ~/.bashrc << 'EOF'

# NVM 설정
export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"
[ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"
EOF

# 적용
source ~/.bashrc
```

### 5.4 Docker 데몬이 실행되지 않음

```bash
# 원인: Docker 서비스가 시작되지 않았음
# 해결:

# Docker 서비스 상태 확인
sudo systemctl status docker

# Docker 서비스 시작
sudo systemctl start docker

# 부팅 시 자동 시작되도록 설정
sudo systemctl enable docker
```

### 5.5 gcloud 인증 만료

```bash
# 원인: 인증 토큰이 만료됨 (보통 몇 시간~며칠 후)
# 해결: 다시 로그인

# 사용자 인증 갱신
gcloud auth login

# 애플리케이션 기본 인증 갱신 (코드에서 GCP 서비스 호출 시)
gcloud auth application-default login
```

### 5.6 포트가 이미 사용 중 ("Address already in use")

```bash
# 원인: 이전에 실행한 프로그램이 포트를 점유하고 있음
# 해결:

# 특정 포트(예: 3000)를 사용 중인 프로세스 확인
sudo lsof -i :3000

# 해당 프로세스 종료 (PID는 위 명령 결과에서 확인)
kill -9 <PID>

# 또는 한 줄로 해결:
# 포트 3000을 사용 중인 프로세스를 찾아서 강제 종료
sudo fuser -k 3000/tcp
```
