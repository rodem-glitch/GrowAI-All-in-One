## 1. 프론트엔드란 무엇인가?

### 1.1 프론트엔드 vs 백엔드

```
사용자가 보는 화면 (프론트엔드)          서버 (백엔드)
┌─────────────────────────┐         ┌─────────────────────┐
│  브라우저 (Chrome 등)      │ ──요청──▶│  API 서버 (FastAPI)   │
│                         │         │                     │
│  - 버튼 클릭             │         │  - 데이터 처리         │
│  - 폼 입력               │ ◀──응답──│  - DB 조회/저장       │
│  - 애니메이션             │         │  - AI 연동            │
│  - 페이지 이동            │         │  - 인증/보안           │
└─────────────────────────┘         └─────────────────────┘
          ▲                                  ▲
     여기를 만듭니다                      Part 1에서 만들었습니다
```

### 1.2 우리가 사용할 기술들

| 기술 | 역할 | 비유 |
|------|------|------|
| **React** | UI를 만드는 라이브러리 | 자동차의 "엔진" |
| **Next.js 16+** | React 기반 풀스택 프레임워크 | 완성된 "자동차" |
| **TypeScript** | 타입이 있는 JavaScript | 맞춤법 검사기 |
| **Tailwind CSS 4** | 클래스 기반 스타일링 | 색칠 도구 세트 |
| **Shadcn UI** | 복사해서 쓰는 UI 컴포넌트 | 레고 블록 세트 |

## 3. React 핵심 개념 (5분 요약)

> Next.js는 React 위에 만들어졌으므로, React 기본을 먼저 이해해야 합니다.

### 3.1 컴포넌트 = 재사용 가능한 UI 조각

```tsx
// 컴포넌트는 "함수"입니다
// HTML처럼 생긴 것을 반환하는 함수 = 컴포넌트
// 이 HTML 같은 문법을 "JSX"라고 부릅니다

// ── 가장 간단한 컴포넌트 ──
function 인사말() {
  return <h1>안녕하세요!</h1>;
  // ↑ 이게 JSX입니다. HTML이 아니라 JavaScript 안의 특별한 문법
}

// ── props(속성)를 받는 컴포넌트 ──
// props = 부모가 자식에게 전달하는 데이터
function 환영메시지({ 이름 }: { 이름: string }) {
  //                  ↑ TypeScript: 이름은 문자열이어야 함
  return <h1>{이름}님, 환영합니다!</h1>;
  //        ↑ 중괄호 안에 JavaScript 표현식 사용 가능
}

// ── 사용법 ──
// <환영메시지 이름="김철수" />
// → 화면에 "김철수님, 환영합니다!" 표시
```

### 3.2 useState = 변하는 값 관리

```tsx
'use client'; // ← 이 줄이 있어야 브라우저에서 상호작용 가능
// ↑ Next.js에서 상태(state)를 쓰려면 반드시 필요!

import { useState } from 'react';
// ↑ React에서 useState 함수를 가져옴

function 좋아요버튼() {
  // useState(초기값)은 [현재값, 변경함수]를 반환
  const [좋아요수, set좋아요수] = useState(0);
  //     ↑ 현재값     ↑ 이걸로 값을 바꿈    ↑ 초기값은 0

  return (
    <button onClick={() => set좋아요수(좋아요수 + 1)}>
      {/* ↑ 클릭하면 좋아요수를 1 증가시킴 */}
      좋아요 {좋아요수}개
      {/* ↑ 값이 바뀌면 화면이 자동으로 업데이트됨 */}
    </button>
  );
}
```

### 3.3 useEffect = 부수 효과 처리

```tsx
'use client';

import { useState, useEffect } from 'react';

function 강의목록() {
  // 강의 데이터를 저장할 상태
  const [강의들, set강의들] = useState([]);
  // 로딩 중인지 표시할 상태
  const [로딩중, set로딩중] = useState(true);

  // useEffect: 컴포넌트가 화면에 나타난 후 실행되는 코드
  useEffect(() => {
    // API에서 강의 목록을 가져오는 비동기 함수
    async function 강의가져오기() {
      // fetch: 서버에 데이터를 요청하는 브라우저 내장 함수
      const 응답 = await fetch('/api/courses');
      // 응답을 JSON(객체)으로 변환
      const 데이터 = await 응답.json();
      // 상태 업데이트 → 화면 자동 갱신
      set강의들(데이터);
      set로딩중(false);
    }

    강의가져오기();
  }, []);
  // ↑ 빈 배열 [] = 컴포넌트가 처음 나타날 때 딱 1번만 실행
  // 만약 [검색어] 라고 쓰면, 검색어가 바뀔 때마다 다시 실행

  // 로딩 중이면 로딩 표시
  if (로딩중) return <p>로딩 중...</p>;

  // 데이터가 준비되면 목록 표시
  return (
    <ul>
      {강의들.map((강의: any) => (
        // map: 배열의 각 요소를 JSX로 변환
        // key: React가 각 항목을 구분하기 위해 필요 (고유값)
        <li key={강의.id}>{강의.제목}</li>
      ))}
    </ul>
  );
}
```

### 3.4 요약 치트시트

```
React 핵심 3가지:

1. 컴포넌트 = 함수가 JSX를 반환
2. useState  = 변하는 값을 관리 (값이 바뀌면 화면 자동 갱신)
3. useEffect = 화면에 나타난 후 실행할 코드 (API 호출 등)
```

## 4. Next.js 16+ 프로젝트 생성

### 4.1 Next.js란?

```
React만 사용했을 때의 문제점:
- 페이지 이동(라우팅)을 직접 구현해야 함
- 검색엔진이 내 사이트를 못 읽음 (SEO 문제)
- 서버에서 데이터를 미리 준비할 수 없음
- API 서버를 별도로 만들어야 함

Next.js가 해결해주는 것:
- 폴더 이름만으로 자동 라우팅 (app/about/page.tsx → /about)
- 서버 사이드 렌더링 (SSR) → SEO 해결
- 서버 컴포넌트 → 서버에서 데이터 직접 조회
- API Routes → 간단한 API를 프론트엔드 프로젝트 안에서 생성
- 이미지 최적화, 폰트 최적화 등 자동 처리

비유: React가 "엔진"이라면, Next.js는 "완성된 자동차"
```

### 4.2 프로젝트 생성

```bash
# ─────────────────────────────────────────────────
# Next.js 16+ 프로젝트 생성
# ─────────────────────────────────────────────────

# npx: npm 패키지를 설치 없이 실행하는 명령어
# create-next-app@latest: Next.js 프로젝트 생성 도구 (최신 버전)
# growai-web: 프로젝트 이름 (이 이름의 폴더가 만들어짐)
npx create-next-app@latest growai-web \
  --typescript \
  --tailwind \
  --eslint \
  --app \
  --src-dir \
  --import-alias "@/*"

# 각 옵션 설명:
# --typescript   : TypeScript 사용 (변수에 타입을 지정하여 버그 방지)
# --tailwind     : Tailwind CSS 포함 (클래스명으로 스타일링)
# --eslint       : ESLint 포함 (코드 품질 검사 도구)
# --app          : App Router 사용 (Next.js 최신 라우팅 방식)
# --src-dir      : 소스 코드를 src/ 폴더에 배치 (구조가 깔끔해짐)
# --import-alias : "@/*"로 import 경로 단축
#                  예: import Button from "@/components/Button"
#                  대신: import Button from "../../../components/Button"

# ─────────────────────────────────────────────────
# 프로젝트 디렉토리로 이동
# ─────────────────────────────────────────────────
cd growai-web

# ─────────────────────────────────────────────────
# 개발 서버 시작
# ─────────────────────────────────────────────────
# 개발 서버: 코드를 수정하면 브라우저가 자동으로 새로고침됨
# http://localhost:3000 에서 결과 확인 가능
# 종료: Ctrl + C
npm run dev
```

### 4.6 Server Components vs Client Components

```tsx

//
// 특징:
// - 서버에서만 실행됨 (브라우저에 JavaScript가 전송되지 않음)

// src/app/lms/page.tsx

  const 응답 = await fetch('https://api.growai.co.kr/courses', {

    <div className="mx-auto max-w-7xl px-6 py-10">
      <h1 className="text-3xl font-bold mb-6">LMS 대시보드</h1>
      {/* 서버에서 가져온 데이터를 바로 렌더링 */}
      <div className="grid grid-cols-3 gap-4">
        {강의들.map((강의: any) => (
          <div key={강의.id} className="rounded-lg border p-4">
            <h3 className="font-semibold">{강의.제목}</h3>
            <p className="text-gray-600">{강의.설명}</p>
          </div>
        ))}
      </div>
    </div>
  );

// ─────────────────────────────────────────────────
// Client Component (클라이언트 컴포넌트)
// ─────────────────────────────────────────────────
//
// 특징:
// - 브라우저에서 실행됨 (JavaScript가 전송됨)
// - useState, useEffect, onClick 등 사용 가능
// - 파일 맨 위에 'use client' 를 반드시 써야 함

// 사용 시점: 버튼 클릭, 폼 입력, 토글 등 상호작용이 필요할 때

// src/components/like-button.tsx
'use client'; // ← 이 한 줄이 "이건 클라이언트 컴포넌트야"라고 선언

import { useState } from 'react';

// 좋아요 버튼: 클릭하면 좋아요 수가 증가
export function LikeButton({ courseId }: { courseId: string }) {
  // useState: 값이 변하면 화면을 자동으로 다시 그림
  const [liked, setLiked] = useState(false);

  return (
    <button

      onClick={() => setLiked(!liked)}
      //              ↑ !liked: true ↔ false 토글 (반전)
      className={`
        px-4 py-2 rounded-lg transition-colors
        ${liked
          ? 'bg-red-500 text-white'     /* 좋아요 누른 상태: 빨간 배경 */
          : 'bg-gray-100 text-gray-700'  /* 안 누른 상태: 회색 배경 */
        }
      `}
      // ↑ 백틱(`)과 ${}: 조건에 따라 다른 클래스를 적용
    >
      {liked ? '❤️ 좋아요 취소' : '🤍 좋아요'}
      {/* ↑ 삼항 연산자: 조건 ? 참일때 : 거짓일때 */}
    </button>
```

## 5. Shadcn UI 설정

### 5.1 Shadcn UI란?

```
일반 UI 라이브러리 (예: MUI, Ant Design):
  → npm install 로 설치
  → 코드가 node_modules 안에 숨어있음
  → 커스텀하기 어려움
  → 라이브러리 버전 올리면 깨질 수 있음

Shadcn UI:
  → 컴포넌트 코드를 내 프로젝트에 직접 복사
  → src/components/ui/ 에 코드가 있음
  → 자유롭게 수정 가능 (내 코드니까!)
  → 버전 문제 없음

비유:
  일반 라이브러리 = 완성된 가구를 사서 사용 (수정 어려움)
  Shadcn UI      = 가구 설계도를 받아서 직접 조립 (자유롭게 변형 가능)
```

## 6. Tailwind CSS 4 기본

### 6.1 Tailwind CSS란?

```
전통적인 CSS:
  1. .css 파일을 만들고
  2. 클래스 이름을 정하고
  3. 스타일을 작성
  → 파일을 왔다갔다 해야 함, 이름 충돌 가능

Tailwind CSS:
  1. HTML/JSX에 클래스 이름을 직접 작성
  2. 끝!
  → 파일 전환 불필요, 이름 충돌 없음

비유:
  전통 CSS = 레시피를 보고 처음부터 요리
  Tailwind  = 반조리 재료 키트로 조립
```

## 8. 상태 관리와 데이터 흐름

### 8.1 상태 관리 전략

```
── GrowAI에서 상태 관리 방법 ──

1. 서버 상태 (API 데이터)
   → 서버 컴포넌트의 fetch (가장 추천!)
   → 또는 React Query / SWR (클라이언트에서)

2. URL 상태 (검색어, 필터, 페이지 번호)
   → useSearchParams() + URL 쿼리 파라미터
   → 새로고침/공유 가능!

3. 로컬 UI 상태 (모달 열기, 탭 선택 등)
   → useState (해당 컴포넌트 안에서)

4. 전역 상태 (로그인 정보, 테마 등)
   → React Context 또는 Zustand

원칙: 최대한 서버 컴포넌트 + URL 상태를 쓰고,
      꼭 필요할 때만 클라이언트 상태를 사용
```

### 8.2 React Context로 전역 상태 관리

```tsx
// ─────────────────────────────────────────────────
// src/contexts/auth-context.tsx
// 인증(로그인) 상태를 전역에서 관리
// ─────────────────────────────────────────────────

'use client';

import { createContext, useContext, useState, useEffect } from 'react';

// 사용자 타입 정의
interface User {
  id: string;       // 사용자 고유 ID
  name: string;     // 이름
  email: string;    // 이메일
  avatar?: string;  // 프로필 이미지 (선택적)
}

// Context에 담길 값의 타입
interface AuthContextType {
  user: User | null;          // 로그인한 사용자 (없으면 null)
  loading: boolean;           // 로딩 중 여부
  login: (email: string, password: string) => Promise<void>;   // 로그인 함수
  logout: () => void;         // 로그아웃 함수
}

// Context 생성 (초기값은 undefined)
const AuthContext = createContext<AuthContextType | undefined>(undefined);
// ↑ createContext: React가 제공하는 전역 상태 도구
// 부모 컴포넌트에서 값을 제공하면, 자식 어디서든 접근 가능

// ── Provider 컴포넌트 ──
// 이 컴포넌트로 감싸진 모든 자식은 auth 상태에 접근 가능
export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  const [loading, setLoading] = useState(true);

  // 페이지 로드 시 로그인 상태 확인
  useEffect(() => {
    async function checkAuth() {
      try {
        // 브라우저의 쿠키/토큰으로 현재 사용자 정보 확인
        const res = await fetch('/api/v1/auth/me');
        if (res.ok) {
          const userData = await res.json();
          setUser(userData);  // 로그인 상태면 사용자 정보 저장
        }
      } catch {
        // 에러 → 비로그인 상태
        setUser(null);
      } finally {
        setLoading(false);
      }
    }
    checkAuth();
  }, []);

  // 로그인 함수
  const login = async (email: string, password: string) => {
    const res = await fetch('/api/v1/auth/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ email, password }),
    });

    if (!res.ok) throw new Error('로그인 실패');

    const userData = await res.json();
    setUser(userData);  // 사용자 정보 저장 → 전역에서 접근 가능
  };

  // 로그아웃 함수
  const logout = () => {
    fetch('/api/v1/auth/logout', { method: 'POST' });
    setUser(null);  // 사용자 정보 초기화
  };

  return (
    // AuthContext.Provider로 값을 제공
    // value에 넣은 것들을 자식 컴포넌트에서 사용 가능
    <AuthContext.Provider value={{ user, loading, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

// ── 커스텀 Hook ──
// useAuth()로 어디서든 인증 상태에 접근
export function useAuth() {
  const context = useContext(AuthContext);
  // ↑ useContext: Context에서 현재 값을 가져옴

  // Provider 밖에서 사용하면 에러 (개발자 실수 방지)
  if (!context) {
    throw new Error('useAuth는 AuthProvider 안에서만 사용 가능합니다');
  }

  return context;
}

// 사용법 1: layout.tsx에 Provider 추가
```

### 9.2 클라이언트에서 API 호출 (Server Action)

```tsx
// ─────────────────────────────────────────────────
// Server Action: 서버에서 실행되는 함수를 클라이언트에서 호출
// 'use server' 지시자로 선언
// form 제출, 데이터 변경 등에 최적
// ─────────────────────────────────────────────────

// src/app/learnform/actions.ts
'use server';
// ↑ 이 파일의 모든 함수는 서버에서 실행됨
// 클라이언트에서 호출하면 자동으로 HTTP 요청이 됨

// revalidatePath: 특정 경로의 캐시를 무효화 (데이터 갱신)
import { revalidatePath } from 'next/cache';
// redirect: 다른 페이지로 이동
import { redirect } from 'next/navigation';

// 강의 생성 Server Action
export async function createCourse(formData: FormData) {
  // FormData: HTML <form>에서 제출된 데이터
  // .get(): 특정 필드의 값을 가져옴
  const title = formData.get('title') as string;
  const description = formData.get('description') as string;
  const category = formData.get('category') as string;

  // 유효성 검사
  if (!title || title.length < 2) {
    // 에러를 반환하면 클라이언트에서 받을 수 있음
    return { error: '제목은 2글자 이상이어야 합니다' };
  }

  // 서버에서 직접 API 호출 (보안 안전)
  const response = await fetch(`${process.env.API_URL}/api/v1/courses`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      // 서버에서만 접근 가능한 API 키
      'Authorization': `Bearer ${process.env.API_SECRET_KEY}`,
    },
    body: JSON.stringify({ title, description, category }),
  });

  if (!response.ok) {
    return { error: '강의 생성에 실패했습니다' };
  }

  const 새강의 = await response.json();

  // /lms 페이지의 캐시를 무효화 (새 데이터 반영)
  revalidatePath('/lms');

  // 새 강의 페이지로 이동
  redirect(`/lms/course/${새강의.id}`);
}
```
